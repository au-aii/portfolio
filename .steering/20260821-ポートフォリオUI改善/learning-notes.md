## フェーズ1: GitHubリンクのアイコン化

**学ぶこと**: SVGの基本構造（`viewBox`と`path`）／`currentColor`によるCSS色の継承の仕組み／テキストをアイコンに置き換えたときにアクセシビリティが失う情報と、`aria-label`での補い方。

### SVGの構造

```svg
<svg xmlns="..." width="16" height="16" viewBox="0 0 16 16">
  <path d="M6.766 11.328c...z"/>
</svg>
```

- **`viewBox="0 0 16 16"`**: 「16×16の座標空間の中にこの絵を描く」という宣言。`width`/`height`属性を消してCSSで`width:1em;height:1em`のように上書きしても、`viewBox`が座標系を保つので絵が崩れない
- **`<path d="...">`**: `d`はペンの軌跡。`M`(move to)で開始点に移動し、`c`(曲線)で曲がりながら線を引く…という命令の羅列。デザインツールが吐き出したものをそのまま使うのが普通で、手で書くものではない

**理解の確認**: `width`/`height`を消してCSS側でサイズ指定しても絵が崩れない理由を、自分の言葉で説明できるか。

### `fill="currentColor"` の意味

`currentColor`はCSSのキーワードで「このSVGを囲んでいる要素の`color`プロパティの値を使う」という意味。`fill`を指定しない/黒固定にすると、ダークモードで黒いアイコンが暗い背景に沈んで見えなくなる。`currentColor`にすることで、既存のテーマ切り替え（`--fg`の値がライト/ダークで変わる仕組み）にアイコンも自動的に乗る。

**理解の確認**: 今の`.hero-links a`に`color`の指定が実際にあるか確認する。無ければ、SVGだけ`currentColor`にしても意味が無い（継承元が無い）。`.hero-links a { color: var(--fg); }`のように明示するか、他の継承経路があるかを確かめる。

### `aria-label` が要る理由

今は`<a href="...">GitHub</a>`とテキストがあるので、スクリーンリーダーは「GitHub」と読み上げる。テキストをSVGに置き換えると読み上げ内容が無くなる（SVGの中身は基本的に無視される）ので、`<a>`に`aria-label="GitHub"`を足して補う。

### 実装前に決めること

1. `<a>`の中身をSVGに完全に置き換えるか、`<svg>...</svg><span class="visually-hidden">GitHub</span>`のように視覚的に隠したテキストを残すか（後者の方がアクセシビリティは堅い）
2. アイコンのサイズをどう決めるか（`width`属性を上書きするか、CSSで`width:1em`にしてfont-sizeに連動させるか）
3. 今の`padding:8px 18px`のままだとアイコン1個には余白が広すぎないか

## フェーズ2: レイアウト調整

**学ぶこと**: 既存クラスを壊さずに新しいバリエーションを追加するCSS設計（`.row--primary`のような命名）／1箇所のCSS変更が複数セクションに一律で波及する「グローバルなセレクタ」の影響範囲の考え方／視覚的な優先順位（強弱）をfont-size・padding・borderなど複数のCSSプロパティの組み合わせでどう表現するか。

### Work以下の強弱づけ

新しいクラスを追加する方式（例: `.row--primary`）と、既存`.row`を直接書き換える方式のどちらを選ぶかで、後から元に戻しやすさが変わる。既存クラスを直接変更すると全項目に影響するため、「一部だけ強調したい」という今回の目的には新クラス追加の方が向いている。

**理解の確認**: どちらの方式が「後から元に戻しやすいか」を考えてから選ぶ。

### セクション間の余白

`h2{margin:84px 0 18px}`という指定は、ページ内の全`<h2>`要素にマッチするセレクタ。つまりこの1行を変えると、Work / Studies / Writing / Research 全セクションの間隔が一律で変わる。

**理解の確認**: なぜこの1行の変更が全セクションに影響するのかを、CSSセレクタの仕組みから説明できるか。

## フェーズ4: インタラクティブなビジュアルの追加

**学ぶこと**: Canvas 2D APIの基本（`getContext('2d')`、`fillRect`、フレームごとの再描画）／`requestAnimationFrame`によるアニメーションループの作り方／`IntersectionObserver`で「画面外にある間は計算を止める」というパフォーマンス最適化のパターン／`prefers-reduced-motion`というアクセシビリティ設定への配慮。

### 既存実装から読み取れるパターン

`index.html`のThomasアトラクタ実装（`#bg`のCanvas）は、以下の型で書かれている。新しいビジュアルもこの型を踏襲すると、既存コードとの一貫性が保てる。

1. `resize()`: 画面サイズに応じてCanvasの解像度とパーティクル数を決める
2. `frame()`: 1フレームごとの状態更新＋描画。`requestAnimationFrame(frame)`で自分自身を再度呼び出してループを作る
3. `IntersectionObserver`: 要素が画面内に入ったら`frame()`を開始、外に出たら`cancelAnimationFrame`で止める（見えない場所で計算を続けるのは無駄なCPU消費）
4. `prefers-reduced-motion: reduce`時は、ループを回さず静止画を1回だけ描画する

**理解の確認**: なぜ「画面外では止める」処理が必要か（ヒントは、複数のビジュアルを1ページに置いたときに起きること）を自分の言葉で説明できるか。
