# 要求内容

## 概要

ポートフォリオサイト（`index.html` / `cv.html`）のUI改善を4項目行う。実装はフロントエンド学習を兼ねて本人が自分の手で書き、AIは計画立案とコードレビューに徹する。

## 背景

- 現状のポートフォリオは1ページ完結のindex.html + 別ページのcv.htmlという静的HTML構成（ビルドツール無し、フレームワーク無し、CSSはインラインの`<style>`）。
- 本人はフロントエンドを動画等で学習中。イメージは掴めているが「実際に書いてみないと分からない」という課題感があり、AIに実装を任せると学びが得られない。
- 4つのやりたいことが会話ベースで出てきたが、優先順位・依存関係・タスク粒度が整理されていない状態だった。

## 実装対象の機能

### 1. GitHubリンクのアイコン化

- `.hero-links`内のテキストリンク「GitHub」を、公式のGitHubマーク（Octiconsの`mark-github`、またはGitHub公式ブランドSVGのインライン埋め込み）に置き換える
- ライブラリ依存を増やさず、SVGを1個直接埋め込む方式を想定（ビルドステップが無いサイトのため）
- ライト/ダークテーマ両方で視認性を保つ（既存の`--fg`/`--muted`トークンに追従させる）

### 2. レイアウト調整

すり合わせの結果、以下3点に絞られた。

- **Heroのリンクボタン**: 現状の`.hero-links`（Work/Zenn/GitHub/CV）を、テキストボタンからアイコンベースの見た目に変更したい。GitHubアイコン化（項目1）と地続きの作業として、他のリンクにも同様の扱いを検討する
- **Work以下の情報密度**: 現状は全項目が同じ見た目の行として並び、単調に見える。案件の規模・重要度で視覚的な強弱（メリハリ）をつけたい
- **セクション間の余白**: 現状84pxで固定されているセクション間の`margin`（`h2{margin:84px 0 18px}`）を見直したい

既存のデザイントークン（`--bg`/`--fg`/`--line`/`--radius`等）とセクション構成（hero / Work / Studies / Writing / Research）自体は維持する。

### 3. 新規ページの追加

- 内容は未定。学習の題材にもする（本人が最初から自分で構造を考える）
- 既存の`cv.html`と同様、独立した`.html`ファイルとして追加し、トップページの`.hero-links`や適切な導線からリンクする

### 4. インタラクティブなビジュアルの追加

- 既存の`index.html`内Canvas実装（Thomasアトラクタのパーティクル背景）のような、動きのある視覚表現を増やす
- 新規ページ、または既存ページの新セクションへの組み込みを想定（配置場所は設計フェーズで決める）

## 受け入れ条件

### GitHubリンクのアイコン化

- [ ] テキスト「GitHub」がSVGアイコンに置き換わっている
- [ ] ライト/ダーク両テーマで視認できる
- [ ] キーボードフォーカス時のアウトライン（`a:focus-visible`）が引き続き機能する

### レイアウト調整

- [ ] `.hero-links`がアイコンベースの見た目に変わっている
- [ ] Work以下のリストに、案件規模に応じた視覚的な強弱がついている（全項目が同一の見た目ではない）
- [ ] セクション間の余白（現状84px）が見直されている
- [ ] 変更後もモバイル幅（〜760px）でレイアウトが崩れない
- [ ] 既存のダークモード対応（`prefers-color-scheme`）が維持される

### 新規ページの追加

- [ ] 新しい`.html`ファイルが追加され、トップページからリンクされている
- [ ] 既存ページと視覚的に統一感がある（同じデザイントークンを使う）

### インタラクティブなビジュアルの追加

- [ ] `prefers-reduced-motion: reduce`環境で静止表示にフォールバックする（既存Canvas実装と同じ配慮）
- [ ] モバイルでも極端に重くならない（既存実装のような画面サイズに応じた負荷調整を踏襲）

## 成功指標

- 4項目すべてが本人の実装で完了し、実際にサイトへ反映されている
- 各タスクが「小さく着手→動かして確認→次」で回せた（一度に大きすぎるタスクにならなかった）

## スコープ外

- dev-agentによる自動実装（本人が書く）
- CMS化・ビルドツール導入・フレームワーク導入など、静的HTML構成自体の変更
- Zenn RSS連携（`api/feed.js`）の変更

## 参照ドキュメント

このリポジトリに`docs/`配下の永続ドキュメントは存在しない（静的サイトのみ）。既存の`index.html` / `cv.html`の実装そのものが唯一の設計方針の参照元。
