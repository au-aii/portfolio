# 設計書

## アーキテクチャ概要

ビルドツール・フレームワーク無しの静的HTML構成。`index.html`と`cv.html`がそれぞれ独立した`<style>`ブロックを持ち、CSS変数（`--bg`/`--fg`/`--muted`/`--line`/`--chip`/`--card`/`--shadow`/`--radius`）でライト/ダーク両テーマを表現している。JSはページ末尾の`<script>`内にIIFEで直接記述（モジュールバンドラ無し）。

```
[ブラウザ]
  ├─ index.html ─ 独自<style> + 独自<script>（Canvas背景 / Zenn RSS取得）
  ├─ cv.html    ─ 独自<style>（index.htmlとトークンを共有するが別ファイル）
  └─ (新規).html ─ 同じトークンを踏襲した独立ページ

[Vercel]
  └─ api/feed.js ─ Zenn RSSをCORS越しに中継するServerless Function
```

新規ページ・新規インタラクティブビジュアルも、この「各ページが自己完結した`<style>`/`<script>`を持つ」パターンを踏襲する（共通CSSファイルへの切り出しは今回のスコープ外）。

## コンポーネント設計

### 1. GitHubアイコン（インラインSVG）

**責務**:

- `.hero-links`内の「GitHub」テキストリンクを、視覚的に認識できるマークへ置き換える

**実装の要点**:

- GitHub公式ブランドマークのSVGパスをそのまま`<a>`要素内に埋め込む（外部ライブラリ・アイコンフォント不要）
- `fill="currentColor"`にして、既存の`color:var(--fg)`継承に乗せる（ライト/ダーク自動追従）
- アクセシビリティのため`aria-label="GitHub"`を`<a>`に付与し、視覚的なテキストが消える分を補う
- 既存の`.hero-links a`のpadding/border設計はそのまま使い、中身だけアイコン+バランス調整用の小さいpaddingにする

### 2. レイアウト調整

**責務**:

- 既存セクション構成を保ったまま、Heroボタン・Work以下の情報密度・セクション余白の3点を調整する

**実装の要点**:

- **Heroリンクボタン**: `.hero-links a`をアイコンベースに変更。GitHubアイコン化（コンポーネント1）と同じインラインSVGパターンを他リンク（Work/Zenn/CV）にも展開する
- **Workの視覚的強弱**: 現状`.row`は全項目が同一の見た目。`facts`チップの有無・件数など既存データから「規模の大きい案件」を判定し、フォントサイズ・パディング・borderの太さ等で強弱をつける。新しいCSSクラス（例: `.row--primary`）を追加する形にし、既存の`.row`はそのまま残す
- **セクション余白**: `h2{margin:84px 0 18px}`の値を調整。変更は全セクション（Work/Studies/Writing/Research）に一律で効くため、1箇所の変更で全体のリズムが変わることに注意する
- 変更は既存のCSS変数・クラス命名規則（`.row`/`.t`/`.m`/`.sub`/`.facts`等）の流儀に合わせる

### 3. 新規ページ

**責務**:

- `cv.html`と同格の独立ページとして、新しいコンテンツ（内容は本人が決める）を提供する

**実装の要点**:

- `cv.html`をテンプレートとして構造をコピーし、`:root`のCSS変数はindex.html/cv.htmlと同じ値を使う（統一感の担保）
- トップページの`.hero-links`（またはfooter等の適切な導線）にリンクを追加

### 4. インタラクティブビジュアル

**責務**:

- 既存のThomasアトラクタ背景と同様、視覚的に動きのある要素を追加する

**実装の要点**:

- 既存実装（`index.html`の`<script>`内、`#bg`のCanvas IIFE）の設計パターンを参考にする:
  - `prefers-reduced-motion: reduce`時は静止画にフォールバック
  - `IntersectionObserver`で画面外に出たら`requestAnimationFrame`を止める（負荷対策）
  - 画面サイズに応じてパーティクル数などの負荷を調整する
- 配置先（新規ページ内 or 既存ページの新セクション）はタスク着手時に決定する

## データフロー

### GitHubアイコン表示

```
1. ページ読み込み時、<a href="https://github.com/au-aii">内のSVGがそのまま描画される
2. ホバー時、既存の.hero-links a:hoverのtransform/background-colorがそのまま効く
3. テーマ切り替え時、fill="currentColor"がvar(--fg)の変化に自動追従する
```

### インタラクティブビジュアルの表示制御

```
1. IntersectionObserverが要素の可視状態を監視
2. 可視かつreduced-motionでない → requestAnimationFrameループ開始
3. 不可視 → cancelAnimationFrameで停止（既存Thomasアトラクタと同じ節電パターン）
```

## エラーハンドリング戦略

このスコープでは新規の非同期通信・外部APIを追加しないため、カスタムエラークラスは不要。既存の`api/feed.js`呼び出し部分（`try/catch`で失敗時は静的リンクのまま残す）と同じ「失敗時は既存表示を壊さずそのまま残す」方針を新規ビジュアル・新規ページでも踏襲する。

## テスト戦略

このリポジトリにはテストフレームワーク・リンタ・ビルドスクリプトが存在しない（静的HTML + Vercel Serverlessのみ）。そのため自動テストの代わりに、各タスク完了時に以下を手動確認する。

### 手動確認項目

- ライトモード / ダークモード（OSの外観設定切り替え、または開発者ツールのレンダリングエミュレーションで両方確認）
- モバイル幅（〜760px）でのレイアウト崩れ
- `prefers-reduced-motion: reduce`環境でのフォールバック動作（新規ビジュアル追加時）
- キーボードのみでのフォーカス移動（`:focus-visible`が機能するか）

## 依存ライブラリ

新規に追加するライブラリ・パッケージは無し（インラインSVG・素のCanvas APIのみで完結させる方針）。

## ディレクトリ構造

```
portfolio/
├── index.html          # 変更: GitHubアイコン化、レイアウト調整、(場合により)インタラクティブビジュアル追加
├── cv.html              # 変更: レイアウト調整（対象になる場合）
├── (新規ページ名).html  # 新規追加
├── assets/              # 新規ビジュアルが画像・動画アセットを使う場合はここに追加
└── api/feed.js          # 変更なし
```

## 実装の順序

1. GitHubアイコン化（最小スコープ・既存パターンの変更のみで完結する練習台）
2. レイアウト調整（既存構造の理解を深めつつ、CSSの手触りに慣れる）
3. 新規ページ追加（構造をゼロから組む練習）
4. インタラクティブビジュアル追加（Canvas API・requestAnimationFrame・IntersectionObserverという最も難度の高い要素）

## セキュリティ考慮事項

- インラインSVGは静的な自作/公式アセットのみを使用し、外部ソースからの動的なSVG読み込みは行わない
- 新規ページに外部入力を扱うフォーム等は追加しない（追加する場合は別途検討）

## パフォーマンス考慮事項

- 新規インタラクティブビジュアルは既存のThomasアトラクタ実装と同様、画面外での停止・reduced-motion対応・画面サイズに応じた負荷調整を必須とする
- 新規ページの画像・動画は既存の`loading="lazy"` / `IntersectionObserver`による遅延読み込みパターンを踏襲する

## 将来の拡張性

ページが増えるにつれて`<style>`の重複が増えるため、将来的に共通CSS（例: `assets/base.css`）への切り出しを検討する余地がある（今回のスコープ外）。
